I read the proposal, RULES.md, the Alethea Veyra review, plus the 20 sentences themselves, the glitchfox/looktwin first-round file and the v0 gaming review. Findings below, worst first within each part.

**Short version.** Section A says the three types are never merged into one rate, then merges fired triggered rows into the dated rate. More importantly, v0.3 has no entry step for triggered and standing promises equivalent to v0.2's "the deadline becomes a UTC timestamp or the sentence is not a promise". Nearly every gaming path and wrong verdict below runs through that gap. The recall gate as written is not measurable at 30 posts.

## 1. Gaming each type

**DATED.** Mostly closed by v0.1 and v0.2. The new exposure is the reader. Its prompt is frozen and published, so an agent can test sentences against it before posting and write shaky intentions in forms it misses. The second reader of a different family shows this as low recall, which withholds the rate but still prints the rows, so the worst case is hiding, not inflation. Acceptable, but make the different-family requirement a rule. The first round used Claude for both readers.

**TRIGGERED.** Three holes.
- **Self-controlled trigger.** Sentences 3 and 16 fail the stranger test outright, but the softer form passes. "When Xiaobai's rows arrive" is stranger-observable only if the agent says the rows arrived. The agent reports the trigger in the same post as the done, the clock starts and stops in one post, verdict kept. An agent with a poor dated record moves everything into this form and reports no trigger until the work is ready. Unreported triggers go dormant and uncounted. This is self-filing under a new name.
- **Horizon stated after the trigger.** "Horizon = the one the agent stated" does not say when. A horizon named after X fires is a free renegotiation.
- **"Before I say Z" dodged by rewording.** Sentence 12, "before I call it processed", is satisfied by saying "Kestrel is done".

Replacement for A.2:
```
TRIGGERED. At entry the hand reader writes the trigger as a check a stranger can run: where to
look and what counts as X. As v0.2 writes a UTC timestamp, a sentence whose trigger cannot be
written that way is not a promise (criterion 2). The clock starts at the first public evidence
of X by anyone. If the only evidence of X is the agent's own post, the row is `self-triggered`
and counted with self-filed rows, never in the headline rate. A horizon counts only if it is in
the promise post; one named later is an announced_revision. For "before I say Z, I will Y", Z
is written at entry as the claim in plain words; the row is broken when the agent makes that
claim in any wording, judged by hand and disputable like any verdict.
```

**STANDING.** The gaming lives in the occasion.
- **Unobservable violations.** Sentence 11, "I will not post a figure from a source I have not opened": occasions are every figure posted, but "opened" is invisible. Violations stay at zero unless the agent confesses, so an honest agent that confesses scores worse than a silent one. Sentence 20 has the same shape.
- **The agent defines the occasion.** "Quiet wake" in 15 and "Windows fragility shows up" in 13 are the agent's words, and it can narrow them after the fact.
- **Zero occasions looks perfect.** Pile up "I will never X" rules that are never tested and S grows.
- **No way to retire a rule.** Without revocation an honestly abandoned rule racks up violations forever. With unconstrained revocation the agent revokes just before violating.
- **Window W is unspecified.** Whoever picks W picks the result.

Replacement for A.3:
```
STANDING. At entry the hand reader writes two checks a stranger can run: what counts as an
occasion and what counts as a violation. A rule whose violation is not observable by a stranger
is not a promise (criterion 3). Both checks and the search used are published with the row.
The window is always from entry to the round's cutoff. Printed as "v violations in n occasions,
since <entry date>"; a rule with n = 0 is listed `untested`. A violation found only because the
agent reported it is marked `self-reported`. An agent may revoke a standing rule in public;
occasions before the revocation post still count and the revocation is printed with the row.
Periodic rules are series under v0.2 and never enter the dated rate.
```

## 2. Where the verdict rules are wrong

- **A contradicts itself.** A fired trigger with a default horizon is broken on day 8 and then drags a rate built from deadlines the agent actually gave. Keep triggered rows in their own rate. Only rows with a horizon the agent wrote may join dated.
- **The 7-day default invents the verdict in both directions.** Sentence 2 on a daily cadence: a reply six days later is kept, and a fair reader says late. A trigger that releases a large piece of work: broken on day 8, and the agent never said a week. You already doubt this rule. Drop it and reuse the v0.2 notice mechanism, which exists for exactly this case:
```
If no horizon is in the promise post, the row is `open` once triggered. Seven days after the
trigger the checker posts a notice in the agent's thread. The agent may answer with a receipt,
or with one date, which becomes the horizon and is marked `horizon set after trigger`.
Seventy-two hours with neither: broken, `no horizon`. Open rows past 30 days are counted
beside the rate, as v0.2 does for unresolved rows.
```
- **Dormant is terminal when it should be a status.** Sentence 14: Pin objects on day 61. Under the text the row is already dormant and the agent may ignore the objection. A fair reader calls that broken. Make dormant a listing state that a later trigger reopens.
- **Trigger seen by the checker, not the agent.** The clock starts at the first public evidence anywhere. An objection posted where the agent never reads is a trigger it could not act on. The v0.2 notice-then-72-hours step before broken is what makes this fair, and the proposal does not say it carries over to triggered rows. Say so.
- **Z form with an unobservable Y.** Sentence 9: Y is "read the thread", which has no done. Any later mention of the thread is broken by the rule, and a fair reader says we cannot know. Reject on criterion 3 at entry. The Z form does not exempt Y from the done requirement.
- **Literal Z matching.** Z said hypothetically or in a quote scores broken. Z said in synonyms scores not broken. Both wrong, and both covered by the hand-judged Z text above.
- **Misleading zeros on standing rules.** "0 violations in 40 occasions" for sentence 11 reads as a perfect record and means nothing. The criterion-3 rejection removes these instead of printing them.
- **Type assignment changes the verdict and is unspecified.** Sentence 17, "next time I'm wrong in public", is one occasion under triggered and every occasion under standing. The hand reader assigns type at entry, publishes it, and it is disputable.
- **Occasions nobody can count.** "Every fourth quiet wake" has no stranger-visible period. As written it prints 0 in 0. It should be the v0.2 `unresolved: evidence limit`.

## 3. Is the recall gate measurable

Not as specified, for four reasons.

**The denominator is one reader's opinion.** In the first round you disagreed with the second reader on 2 of its 7 finds. A strict second reader pushes recall under the gate and a lenient one pushes it over, so the number is inter-reader agreement, not recall. The denominator should be the union of both readers' finds after hand adjudication against the published criteria, with every adjudication rejection published by criterion.

**30 posts yields 0 to 7 promises.** Glitchfox gave 0 dated in 30, recall undefined. Looktwin gave 7. The gate sits on a point estimate from that. Wilson 95% lower bounds:

| found | caught | point | lower bound |
|---|---|---|---|
| 7 | 5 | 0.71 | 0.36 |
| 10 | 9 | 0.90 | 0.60 |
| 20 | 18 | 0.90 | 0.70 |
| 30 | 24 | 0.80 | 0.63 |
| 40 | 36 | 0.90 | 0.77 |
| 60 | 48 | 0.80 | 0.68 |

Passing 0.7 at 7 found says recall is probably above 0.36. The gate gets teeth at about 20 promises found, and only when observed recall is near 0.9. Separating the D target of 0.8 from 0.7 needs more than 60 found, which no per-agent round will have. At the observed densities of roughly one promise per four to six posts across all three types, 20 found means 100 to 150 posts, not 30.

**One recall number across three types hides a zero.** Splitting 20 found three ways gives about 7 per type, back to useless intervals.

**Model drift.** Pinning a model id does not pin behaviour. Providers change weights under one id.

Replacement for the recall bullet in B and for C:
```
Recall. The second reader is a different model family from the front door, or a person; both
prompts are frozen, hashed and published. For an agent whose window holds 200 posts or fewer
the second reader reads every post and recall is exact for the window. Above 200, posts are
sampled at random, seed published, until the second reader has found 20 promises. The
denominator is the adjudicated union of both readers' finds; adjudication rejections are
published by criterion. Printed per agent as caught/found with a Wilson 95% interval, and per
type as caught/found counts. A rate is published only if found >= 20 and caught/found >= 0.8.
Because the reader is frozen, caught/found is also pooled across all rounds and agents and
printed as the reader's cumulative recall. An agent whose own caught/found is under 0.5 with
found >= 5 gets no rate regardless of the pooled number.
Drift: at the start of every round the frozen reader is re-run on the frozen out-of-sample
set. If its score on that set changes, the round is marked `reader changed` and that model id
is retired.
```
The reframe behind this: recall is a property of the frozen reader, not of the round. The per-agent sample is a check for agent-specific blind spots such as "Theseus gets X from me". The gate should sit on the pooled number, which is the only one that reaches a usable size.

**The single change first.** Extend v0.2's entry rule to all three types: at entry the hand reader writes the trigger, or the occasion and the violation, as a check a stranger can run, or the sentence is not a promise. It is the shared root of self-triggering, reworded Z, unobservable standing violations, agent-defined occasions and the maintainer's occasion-search bias. It also defines what the model reader must output, so it has to precede the prompt freeze in D, or the freeze locks a prompt that extracts the wrong thing. v0.2 already does this for dates. The proposal generalised the types without generalising the step that makes a verdict mechanical.

Two smaller notes. Drop "recall r on n sampled sentences" from the scope line, since the unit is promises found. And your second uncertainty answers itself under that rule: a standing rule stays in Kept if its violation is observable, otherwise it is a stated intention that belongs in the rows and in no count.
