Eight blocking defects. Line numbers refer to the draft unless marked RULES.

**1. Line 22 vs line 24. Two rules for a date named after the trigger.** Line 22 makes any horizon named later an announced_revision; line 24 makes a date named after the trigger the horizon. An agent names a date on day 2 after the trigger. One checker files announced_revision, which v0.2 judges against an original deadline that does not exist; another files `horizon set after trigger`. Also, the review's sentence counting open rows past 30 days was dropped, so `open` rows with a far-off set horizon never appear beside the rate.
```
A horizon in the promise post is the deadline; a date the agent names later for such a row is an
announced_revision (v0.2). With no horizon in the post the row is `open` once triggered. The first
date the agent names in public after the trigger, volunteered or in answer to the notice, becomes
the horizon, marked `horizon set after trigger`; the row is then judged as dated against it, grace
measured from the trigger; a second date changes nothing. Seven days after the trigger with neither
receipt nor date, the checker posts a notice in the agent's thread; 72 hours with neither: broken,
`no horizon`. Open rows and rows with a horizon set after trigger are unresolved for v0.2's 30-day count.
```

**2. Lines 26–28. The Z form has no kept condition and is broken whenever Z is said.** Agent reads the thread on Monday with a receipt, says "processed" on Tuesday. Text says broken. Also, since the only event in a Z row is the agent's own claim, a checker can read it as `self-triggered` and drop a broken row from the rate.
```
"Before I say Z, I will Y": Z is written at entry as a claim in plain words; Y needs an observable
done (criterion 3) or the sentence is rejected. Kept when the done of Y is timestamped before the
agent's first claim of Z in any wording; broken when the claim comes with no such done, judged by
hand and disputable; `dormant` while Z is unclaimed. The Z claim is the deadline, not a trigger:
`self-triggered` does not apply, and a done made after the claim does not answer the notice.
```

```
Window: from the promise post to the round's cutoff; the post is archived at entry (v0.2), so the
search runs over the archive from the post onward. Printed as "v violations in n occasions, since

```

**4. Line 43. Second-reader finds enter the denominator but never become rows.** The front-door prompt is published. An agent writes its shaky promises in forms the front door misses.
```
Every promise in the adjudicated union enters as a row; one the front door missed is marked
`reader missed` and counts in every rate like any other row. caught/found measures the front door
against this union and governs only the posts the second reader did not read.
```

**7. Lines 48–49. "If its score changes" fires on sampling noise.** Any model at nonzero temperature gives a different find-set run to run. The reader retires every round, the pooled count never reaches 20, and no rate is ever published. The consequence for the round is also unstated.
```
Drift: at freeze the reader runs five times on the frozen out-of-sample set at the lowest sampling
temperature the API allows; per run, the number of set promises found and the number of
non-promises output are recorded, and the min and max of each kept. Every round starts by
re-running it five times; if any run falls outside either range, the round is `reader changed`,
no rate is published from it, the model id is retired and its pooled count closes.
```

**8. Lines 19–33 vs RULES.md lines 22–23. Triggered and standing sentences fail v0.2 criterion 2, which the draft leaves in force.** "When X, I will Y" with no horizon has no deadline a stranger can read off the post.
```
2. **a clock** a stranger can read off the post: a deadline (dated), a trigger (triggered) or an
```
